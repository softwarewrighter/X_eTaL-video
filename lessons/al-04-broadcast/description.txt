Array Languages, episode 4. What happens when two arrays of different shapes meet? In X_eTaL the rule is short: a single value extends to every item (scalar extension), arrays of the same shape combine item by item, and any other pair is an error that names both shapes. To combine other shapes you say how: reshape a vector onto each row, reshape and transpose it down the columns, use the rank form, or take every pair with table. Then the same two expressions in APL, J, BQN, K and NumPy: APL needs an axis or the rank operator, J, BQN and K match axes from the front, and NumPy matches them from the back and stretches length-one axes, which can turn a mistake into an answer of the wrong shape; in X_eTaL the same table is asked for with table. Every argument and result is drawn as a box, so each shape shows, and arrays appear as cubes rendered by Blender from X_eTaL.
